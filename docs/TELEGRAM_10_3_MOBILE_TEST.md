# Telegram 10.3 手机实机测试

这份清单用于测试本分支，不代表自动化测试已经替代真实 Telegram 客户端。

官方接口依据：[Telegram Bot API 10.3 changelog](https://core.telegram.org/bots/api-changelog) 和 [Telegram Bot API](https://core.telegram.org/bots/api)。

## 准备

1. 把本分支部署到测试环境，不要覆盖生产 `main`。
2. 准备主 Bot、客服 Bot、一个测试群和两个普通测试账号 A/B。
3. 把两个 Bot 加入测试群。主 Bot 需要发送欢迎消息的管理员权限。
4. 若要验证客服 Bot 的“应用层完全静默”，只在测试 Bot 临时关闭 BotFather Privacy Mode；测试后重新开启。生产环境建议保持 Privacy Mode 开启。

## 1. 客服 Bot 群聊隔离

用账号 A 在群里依次发送：

- 普通文字
- 图片
- 语音
- 文件
- 视频、圆形视频、音频和 GIF
- 贴纸、位置、地点和联系人
- 投票、骰子和 Live Photo（客户端支持时）

预期：客服 Bot 完全不回复，管理员私聊没有新工单或转发。

再发送：

- `@你的客服Bot`
- `/support`

预期：客服 Bot 仍完全静默，0 回复、0 工单、0 管理员转发、0 限流记录。客服入口只应由主 Bot 的按钮或客服 Bot 私聊链接提供。

在频道发布普通内容和 `/support`。

预期：客服 Bot 完全忽略。

## 2. 私聊客服

账号 A 点击“💬 联系客服”，进入客服 Bot 私聊，并依次发送文字、图片、语音、文件、视频、圆形视频、音频、GIF、贴纸、位置、地点、联系人、普通投票、骰子和 Live Photo（客户端支持时）。

预期：

- 输入框自动进入回复状态。
- 第一次私聊消息创建一个工单。
- 后续消息进入同一工单。
- 只有接单客服收到完整内容。
- 客服收到的是 Telegram 原消息副本，caption、媒体和消息格式保持不变。

再尝试发送 quiz 投票、付款消息或其他系统消息。

预期：Telegram 无法安全复制时，客服 Bot 给出友好提示；不会报错、不会关闭已有工单，也不会把付款或系统事件转给客服。

账号 B 同时创建另一个工单。

预期：A/B 工单、消息和负责人互不串联。

## 3. 群欢迎与购买隐私

让账号 A 新加入测试群。

预期：

- A 能看到欢迎消息和“🚀 开始使用”。
- 账号 B 看不到 A 的临时欢迎内容。
- 群时间线没有公开套餐、余额、订单或付款信息。

账号 A 点击“⭐ 购买额度”。

预期：

- 支持 Telegram 10.3 时，原临时欢迎消息直接编辑成 A 的私密购买表格。
- 表格使用紧凑布局，只有 A 可见。
- 不支持临时编辑时，Telegram 跳到主 Bot 私聊购买页。
- 群里不出现公开套餐或余额。

让账号 B 重复点击并对比。

预期：A/B 各自看到自己的临时消息，临时消息编号和接收用户不串。

## 4. Telegram 10.3 展示

- 在私聊打开购买页和余额页：确认紧凑表格可读。
- 运行一个带较长状态或日志的 Agent 任务：确认详情显示为可展开引用。
- 在客服私聊点击开始：确认输入框进入强制回复状态。
- 若测试账号已经有 Community：添加、移除或加入 Community chat，确认主 Bot 不把系统事件当作 AI 提问。

## 5. 已有功能回归

依次确认：

- 流式回复可以停止，停止后已生成内容被保留。
- 私聊提问后始终只有一条持续编辑的回复；完成后不出现第二份答案，流式消息也不会自动消失。
- 账号 A/B 同时提问，停止 A 只停止 A，B 的流式回复继续；双方 message ID 和答案不串。
- 用 Telegram 原生格式发送加粗、斜体、代码和引用文本，Bot 不报实体解析错误。
- 回复一条旧消息或引用一段文字提问；引用参数不可用时应降级为普通回复，不重复发送。
- Rich Message 流式输出正常，失败时在同一条消息上降级。
- 彩色按钮、disabled 按钮和普通 Rich Message 按钮正常。
- Agent 完成报告中的 `tg-document` 可以打开。
- 群欢迎仍是临时消息。

## 6. 主 Bot 群指令与 fan-out 隔离

账号 A 在测试群发送 `/help` 和 `/whoami`。

预期：

- 回复只对 A 可见；私密接口不可用时只给 A 打开主 Bot 私聊入口。
- B 不应收到群内私密回复，也不应收到任何主 Bot 私聊。
- `/whoami` 群内只向 A 显示用户 ID、群组 ID、用户名和管理员状态。

再让 A 点击欢迎消息中的购买入口。

预期：B 和其他成员不会收到私聊，不会看到 A 的套餐、余额或订单。一次群内事件绝不能遍历历史用户或群成员进行私聊 fan-out。
