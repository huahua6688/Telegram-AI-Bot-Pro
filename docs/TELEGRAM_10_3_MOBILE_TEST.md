# Telegram 10.3 手机实机测试

这份清单用于测试本分支，不代表自动化测试已经替代真实 Telegram 客户端。

官方接口依据：[Telegram Bot API 10.3 changelog](https://core.telegram.org/bots/api-changelog) 和 [Telegram Bot API](https://core.telegram.org/bots/api)。

## 准备

1. 把本分支部署到测试环境，不要覆盖生产 `main`。
2. 准备主 Bot、客服 Bot、一个测试群和两个普通测试账号 A/B。
3. 把两个 Bot 加入测试群。主 Bot 需要发送欢迎消息的管理员权限。
4. 若要验证客服 Bot 的“应用层忽略普通群消息”，只在测试 Bot 临时关闭 BotFather Privacy Mode；测试后重新开启。生产环境建议保持 Privacy Mode 开启。

## 1. 客服 Bot 群聊隔离

用账号 A 在群里依次发送：

- 普通文字
- 图片
- 语音
- 文件

预期：客服 Bot 完全不回复，管理员私聊没有新工单或转发。

再发送：

- `@你的客服Bot`
- `/support`

预期：只出现“💬 联系客服”入口；不会创建工单，也不会转发内容给管理员。支持临时消息的客户端只让账号 A 看到，旧客户端最多显示不含隐私信息的私聊入口。

在频道发布普通内容和 `/support`。

预期：客服 Bot 完全忽略。

## 2. 私聊客服

账号 A 点击“💬 联系客服”，进入客服 Bot 私聊并发送一段文字，再发送一张图片。

预期：

- 输入框自动进入回复状态。
- 第一次私聊消息创建一个工单。
- 后续消息进入同一工单。
- 只有接单客服收到完整内容。

账号 B 同时创建另一个工单。

预期：A/B 工单、消息和负责人互不串联。

## 3. 群欢迎与购买隐私

让账号 A 新加入测试群。

预期：

- A 能看到欢迎消息和“🚀 开始使用”。
- 账号 B 看不到 A 的临时欢迎内容。
- 群时间线没有公开套餐、余额、订单或付款信息。

账号 A 点击“⭐ 购买额度”。

预期：

- 支持 Telegram 10.3 时，原临时欢迎消息直接编辑成 A 的私密购买表格。
- 表格使用紧凑布局，只有 A 可见。
- 不支持临时编辑时，Telegram 跳到主 Bot 私聊购买页。
- 群里不出现公开套餐或余额。

让账号 B 重复点击并对比。

预期：A/B 各自看到自己的临时消息，临时消息编号和接收用户不串。

## 4. Telegram 10.3 展示

- 在私聊打开购买页和余额页：确认紧凑表格可读。
- 运行一个带较长状态或日志的 Agent 任务：确认详情显示为可展开引用。
- 在客服私聊点击开始：确认输入框进入强制回复状态。
- 若测试账号已经有 Community：添加、移除或加入 Community chat，确认主 Bot 不把系统事件当作 AI 提问。

## 5. 已有功能回归

依次确认：

- 流式回复可以停止，停止后已生成内容被保留。
- Rich Message 流式输出正常。
- 彩色按钮、disabled 按钮和普通 Rich Message 按钮正常。
- Agent 完成报告中的 `tg-document` 可以打开。
- 群欢迎仍是临时消息。
